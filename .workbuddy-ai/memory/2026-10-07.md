## UI overhaul — modern macOS look (src/Noto.App)
- **Tokens** (`Themes/ThemeTokens.cs`): retuned to Apple system greys/accents; added a `sidebar` background token.
  All text tokens still pass WCAG AA on canvas/surface/sidebar/raised (verified by `ThemeTests` + a local script).
- **Icons** (`Views/AppIcons.cs`): new monochrome vector set (24x24 paths) exposed as `PathIcon` via
  `{v:Icon Name}` markup extension and `RowConverters.Icon` for data-bound names. Emoji are gone from the
  UI; the only emoji left is the legacy alias map (old DB icon strings -> semantic names) for backward compat.
- **Stored icon names**: `Preset.Icon` and `WorkspaceTemplate.Icon` are now semantic names
  (`sprint`, `zen`, `deadline`, `habit`, `kanban`, `accountability`, `work`, `personal`, `health`, `side`).
- **Shell** (`Views/MainWindow.axaml`): extended client area with native traffic lights, unified 52px toolbar
  (nav left, centered title, actions right), icon-rail sidebar, animated inspector.
- **Responsive**: `ShellViewModel.ViewportWidth` is pushed from the window. Breakpoints: sidebar collapses and
  toolbar labels hide below 880px; inspector hides below 1000px. Fixed the "buttons clip on resize" complaint.
  Guarded against tiny first-layout sizes (MinViewportWidth = 320) to avoid a startup flash.
- **Motion** (`Themes/Styles.axaml`): all transitions live under `Window.motion` (reduce-motion gated).
  Exponential easing (`CubicEaseOut/InOut`, `ExponentialEaseOut`). Note: this Avalonia build has **no**
  `TransformOperationsTransition` and easing types are direction-specific (`CubicEaseOut`, no `EasingMode`) —
  used `DoubleTransition`/`BrushTransition`/`ThicknessTransition` instead.
  Page swap = new page fades in (code-behind sets opacity 0 -> 1); a `CrossFade` page transition left a muddy
  ghost of the old page, so it was dropped.
- **Tests**: updated glyph assertions; added `Narrow_window_adapts_instead_of_clipping` (renders a narrow window
  and asserts the shell adapts). Screenshots via `NOTO_SCREENSHOTS=<dir> dotnet test tests/Noto.App.Tests`.

## Sidebar rail fix (follow-up)
- Bug: the sidebar had a double horizontal inset (`DockPanel Margin="8"` + `Margin="8,0,8,x"` on the inner
  stacks), so the collapsed 56px rail left only ~24px for buttons -> icons were off-centre and the workspace
  row clipped (4 columns + 30px of `ColumnSpacing` needed ~49px).
- Fix: single inset (`DockPanel Margin="8,0"`); nav/workspace rows are now `Grid`s (gap moved onto the label's
  `Margin` so a hidden label contributes nothing). Added `ShellViewModel.IsSidebarCollapsed`.
- Rail behaviour (`Styles.axaml`): `Button.nav.collapsed` centres the icon (Padding 0,6). Workspace rows keep
  `Stretch` + a centred inner `Grid.wsRow`, hide the colour tick and the count pill, and show a 7px accent dot
  (`Border.wsDot`) in the corner instead. The colour tick moved to the row's left edge as an overlay so
  workspace icons line up with the nav icons.
- Visibility for `.wsBadge`/`.wsDot` uses ONE guarded "turn on" rule each
  (`Button.wsTab:not(.collapsed) ...` / `Button.wsTab.collapsed ...`); relying on selector specificity to
  override a `.show` rule did NOT work — Avalonia kept the badge visible.
- Test harness: `ScreenshotTests.Snap` -> `async SnapAsync`, which pumps the dispatcher (~400ms) so transitions
  settle before capture. Disabling motion instead (`SetReduceMotion(true)`) produced a *stale* frame because no
  render was queued. Added `rail-light.png` (user-collapsed rail at full width).
